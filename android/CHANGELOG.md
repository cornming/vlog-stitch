# 更新紀錄

格式說明：每個版本一個 `## v<versionName>` 區塊，底下的內容會自動變成 GitHub
Release 的說明文字，App 裡的「檢查更新」和「更新紀錄」讀的就是這段。

## v1.5.0

介面改版第一批，處理實際用起來最卡的地方。

- **片段有縮圖了**。先前只顯示檔名，而手機拍的檔名長得幾乎一樣，根本分不出
  哪段是哪段。現在每段都有畫面，另外顯示長度、解析度、是不是 HDR。
- **匯出完可以直接播放和分享**，不用再跑去相簿找檔案。分享可以直接丟 YouTube。
- **不再要你選匯出方式**。改成選好影片後直接告訴你後果：能不能直接接合、
  會不會重新編碼。真的想手動指定的話，選單裡還有。
- **片段清單會記住**。App 被系統回收或關掉再開，選好的片段還在。
- **改成拖曳排序**，取代原本的上下箭頭。抓右邊的握把拖動。
- 選單新增「清空片段」。

## v1.4.0

修正更新一直裝不起來的根本原因。

安裝時出現「未安裝應用程式」，是因為 Android 規定覆蓋安裝必須使用同一把
簽章金鑰。原本 Gradle 設定成用 debug 簽章，而 debug 金鑰是建置機器自動
產生的；GitHub Actions 每次都是全新的 runner，等於每次建置都換一把金鑰。
實測 v1.0.0 到 v1.3.0 的憑證指紋確實全部不同。

改用固定金鑰後，這一版之後的更新都能直接覆蓋安裝。

**這一版要先解除安裝舊版才裝得起來**，因為舊版是用那些隨機金鑰簽的。
只有這一次需要這樣做。

## v1.3.0

專門處理更新下載裝不起來的問題。

- **改成自己下載 APK**，不再交給系統的 DownloadManager。原本那條路失敗時
  什麼線索都沒有，而且要靠廣播回報，App 被切走就收不到。現在每一步都寫進
  詳細記錄：連線、轉址、總大小、下載進度、檔案大小、交給安裝程式，
  哪一步斷掉一眼就看得出來。
- **補上「允許安裝不明應用程式」的檢查**。這個權限沒開的話，安裝畫面叫出來
  也會被系統擋掉，而且不會有明顯提示。現在會先問，並直接帶你到設定頁。
- 下載會顯示百分比與 MB 數，失敗時提供改用瀏覽器的選項，且用選擇器開啟，
  不會再被某個 App 的內建瀏覽器接走。

## v1.2.0

v1.1.0 的轉封裝成功了：20 分鐘的素材 63 秒接完，約 19 倍速，聲音正常，
影像編碼器顯示「無（轉封裝）」，代表完全沒有重新編碼。這一版修掉它暴露的三個問題。

- **匯出完成後 App 沒有回應**：成品有 3GB，而複製到相簿那一步跑在主執行緒上，
  UI 被卡死才跳出 ANR。改到背景執行緒，複製期間進度條會轉、狀態列會說明在存檔。
- **更新下載失敗**：原本用開啟網址的方式，會被 App 內建瀏覽器接走。改用系統的
  DownloadManager 直接下載，抓完自動跳出安裝畫面，不再經過瀏覽器。
- **介面太陽春**：整個重做，改用跟網頁版同一套視覺——深板岩底色配琥珀色重點，
  卡片式分區，底部固定操作列。

其他改進：

- 加上成品長度與依比例分段的時間軸，跟網頁版一樣
- 每段會顯示各自的長度
- 匯出方式改成三顆膠囊按鈕，選中會說明那個模式在做什麼
- 詳細記錄改成可收合

## v1.1.0

修掉 v1.0.0 實機測試發現的兩個問題。

- **匯出失敗（錯誤代碼 4002）**：Pixel 錄的是 10-bit HDR 影片（BT.2020 + HLG），
  Transformer 預設會重新編碼，而裝置上的 HEVC 編碼器初始化不起來。改為預設
  強制轉封裝，完全不碰編碼器——同一支手機拍的素材規格一致，本來就不需要重編。
- **畫面被狀態列蓋住**：Android 15 起強制邊到邊顯示，版面沒有處理系統列邊界。

其他調整：

- 新增模式選擇：自動（先試轉封裝，失敗才重編）／只轉封裝／重編轉 SDR
- 重新編碼時會先把 HDR 色調對應成 SDR，並固定輸出 H.264，避開 HEVC 編碼器
- 匯出前會逐段印出實際規格：解析度、fps、旋轉、色彩轉換曲線與是否為 HDR

## v1.0.0

第一個可安裝的版本，先確認基本流程走得通。

- 多選影片，可調整順序、移除
- 用 Media3 Transformer 接成一支 mp4，走系統的硬體編解碼器
- 規格一致時自動只做轉封裝，不重新編碼
- 成品直接存進相簿的 Movies / vlog-stitch，不用再下載
- 內建檢查更新與更新紀錄，有新版會跳出說明
