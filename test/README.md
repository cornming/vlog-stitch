# 測試

兩套測試，測的都是 `../index.html` 這一份會上線的程式碼，不是複製一份。

| | 指令 | 驗什麼 |
|---|---|---|
| 匯出引擎 | `./run.sh` | 用真的影片和照片跑完整匯出，量成品的長度、聲音和畫面 |
| 操作流程 | `node browser.js` | 用真的瀏覽器走一遍：選檔 → 快速成片 → 確認字幕 → 轉檔 |

測試素材都是 `make-fixtures.sh` 用 ffmpeg 當場產生的，不進版本庫。

## 匯出引擎（Node）

```bash
npm install
./run.sh
```

`run.sh` 直接從 `../index.html` 把主程式抽出來，接上 Node 版的 mediabunny
（`@mediabunny/server` 提供編解碼器），再用測試素材跑完整流程。有任何一項不符合預期，
結束代碼就不是 0。

**素材怎麼設計的**

- 三段同規格的影片（1080x1920 / 60fps / H.264 + AAC），各自用 300、600、900Hz 的音調。
  某個時間點聽到哪個頻率，就知道播到哪一段，**接續順序**和**音畫同步**都能直接量。
- 一段規格刻意不同的 `odd.mp4`（720x1280 / 44.1kHz 單聲道 / 1200Hz），驗證自動退回與換取樣率。
- 三張純色照片（紅、綠、藍，比例各不相同）。某個時間點畫面是什麼顏色，就知道是哪一張；
  交叉淡化到一半應該兩種顏色都看得到；套了黑白應該變成灰色。

**涵蓋範圍**

- 接影片：快速接片、重新編碼，有裁切與無裁切，規格不一致時自動退回，帶字幕
- 只有影片但開了效果：維持快速接片，效果不套用
- 照片：純照片、照片與影片交錯、照片動態、交叉淡化、黑白色調、模糊填滿、字幕燒在照片上
- 聲音：配樂淡入淡出、照片段只有配樂、影片原音準時進出（誤差在幾十毫秒內）、
  有原音時壓低配樂、沒有配樂時照片段是靜音、全照片且沒有配樂時沒有聲音軌、
  取樣率不同的片段混音、原音音量減半
- 邏輯：離線草稿的文字、字幕跟著素材換順序／改長度／被移除／被裁切、依拍攝時間排序、
  EXIF 拍攝時間、AI 字幕的請求內容與回應解析、三首內建配樂的波形、逐塊換取樣率

**測不到的部分**

Node 沒有 `VideoFrame`，所以影片的 `drawWithFit()` 畫不出實際畫面，重新編碼成品裡
**影片那幾段是黑畫面**。影格數、時間戳、聲音、長度都是真的，只有影片的畫素內容驗不了。
照片不經過 `VideoFrame`，是真的畫出來的，所以顏色驗得到。

Node 也沒有 `<video>`、Web Audio 和真正的 WebCodecs，這些留給下面的瀏覽器測試。

## 操作流程（瀏覽器）

```bash
npm install playwright
npx playwright install chromium
node browser.js              # 加 SKIP_ASR=1 可以略過要下載模型的聽打
```

用 Playwright 開一個手機尺寸的 Chromium，照使用者的操作點過去，成品一樣用 ffmpeg 量。
截圖和成品的影格會存到 `shots/`，可以直接打開來看畫面對不對。

**涵蓋範圍**

- 選照片和影片、縮圖、加入照片後自動套用的預設效果
- 快速成片：依 EXIF 拍攝時間排序、離線草稿、停在字幕確認
- **字幕確認真的擋得住轉檔**：按確認才開始；確認過沒再動就不再問；改過字幕會再問；
  按「回去修改」不會轉檔
- 成品的長度、影片段的原音、照片段的配樂
- 換色調和轉場、改用自己的音樂檔
- AI 看圖寫字幕：攔下送往 `api.anthropic.com` 的請求，檢查模型、標頭、圖片和結構化輸出的設定，
  再回一個假的回應，確認字幕有依序套到每段素材
- 預覽、即時錄製模式
- 帶旋轉資訊的照片會轉正、解不開的檔案會擋下來並提示
- 有照片但沒有字幕時，匯出前會問要不要自動寫草稿
- 只有影片時維持快速接片，不會被照片功能影響
- 影片聽打：實際下載 Whisper tiny 跑一次

**測不到的部分**

- AI 看圖寫字幕沒有打真正的 API（那需要金鑰和額度），所以模型實際寫出來的字幕品質、
  API 對這組參數的實際反應都沒有驗到，只確認了送出去的請求是對的。
- 測試跑的是桌機的 Chromium。Android Chrome 和 iOS Safari 的行為（檔案選擇器、
  HEIC、記憶體、硬體編碼器）要實機才知道。
- 配樂好不好聽、轉場順不順，要人自己看 `shots/` 和成品。
